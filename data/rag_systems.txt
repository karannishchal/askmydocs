Retrieval-Augmented Generation, or RAG, combines a retrieval system with a large language model to produce answers that are grounded in an external knowledge source rather than relying solely on the model's parametric memory. The core motivation is to reduce hallucination and allow the system to answer questions about information that was not present in the model's training data, such as private documents or recent events.

A typical RAG pipeline has four stages. First, documents are ingested and split into chunks small enough to fit usefully into a retrieval index while still preserving enough context to be meaningful on their own. Second, each chunk is embedded and stored in a vector index. Third, at query time, the user's question is embedded and used to retrieve the most relevant chunks. Fourth, those chunks are inserted into a prompt alongside the original question, and a language model generates an answer conditioned on that retrieved context.

Chunk size is an important design decision. Chunks that are too small lose surrounding context and can be retrieved without enough information to answer a question fully. Chunks that are too large dilute the relevance signal, since a chunk might contain one relevant sentence buried among many irrelevant ones, making it harder for the retriever to distinguish it from a chunk that is only tangentially related.

A well-designed RAG system should also be able to recognize when its retrieved context does not actually answer the question, and say so, rather than generating a fluent-sounding but unsupported answer. This is typically enforced through prompt instructions that explicitly tell the model to rely only on the provided sources and to acknowledge insufficient information.

Evaluating a RAG system requires assessing both the retrieval stage and the generation stage separately. Retrieval can be evaluated using standard IR metrics such as Recall@k, independent of what the language model eventually generates. Generation quality can be evaluated using faithfulness metrics, which check whether the generated answer is actually supported by the retrieved sources, as well as answer relevance, which checks whether the answer addresses the question that was asked.
