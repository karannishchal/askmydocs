Information retrieval systems are typically organized as a pipeline with two stages: a fast, high-recall retrieval stage that narrows a large corpus down to a smaller candidate set, followed by a slower, high-precision ranking stage that orders those candidates by relevance. This two-stage design exists because computing an expensive relevance score for every document in a large corpus is computationally infeasible at query time.

BM25 is a classic lexical retrieval algorithm based on term frequency and inverse document frequency. It scores documents by how often query terms appear, adjusted for document length and how rare those terms are across the whole corpus. BM25 is fast, requires no training, and performs well on queries with distinctive keywords, but it struggles with queries that are semantically similar to a document without sharing exact vocabulary.

Dense retrieval addresses this limitation by encoding both queries and documents into vector embeddings using a neural network, typically a transformer-based bi-encoder. Similarity between a query and a document is then computed as a distance metric, commonly cosine similarity, between their embeddings. Dense retrieval can match paraphrases and synonyms that BM25 would miss, but it can underperform on queries containing rare identifiers, numbers, or exact phrases that a keyword match would catch easily.

Hybrid retrieval combines sparse and dense signals to get the benefits of both. A common approach is Reciprocal Rank Fusion, which merges two ranked lists by summing a score based on each document's rank position in each list, rather than trying to normalize incompatible raw scores onto the same scale.

Re-ranking is often applied after initial retrieval, using a more computationally expensive model such as a cross-encoder that jointly processes the query and each candidate document together, rather than encoding them independently. Cross-encoders tend to be more accurate than bi-encoders because they can model fine-grained interactions between query and document terms, at the cost of being too slow to run over an entire corpus.

Retrieval quality is commonly measured using Recall@k, which checks whether the relevant document appears anywhere in the top k results, and Mean Reciprocal Rank, which rewards systems that place the relevant document closer to the top of the ranked list. NDCG, or Normalized Discounted Cumulative Gain, is used when there are multiple relevance grades rather than a single correct answer, and it accounts for the position of every relevant document in the ranking, not just the first one.
